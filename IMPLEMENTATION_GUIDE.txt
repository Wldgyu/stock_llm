Stock AI 상세 구현 및 설정 안내

현재 코드의 설정과 동작을 설명하는 참고 문서입니다. 설치와 기본 실행은 README.md를 참고하세요.
모델 변경 이력이나 프론트 사용법은 포함하지 않습니다.

인증 및 환경 설정

프로젝트 폴더에서 예제 설정을 복사하고 .env의 필요한 항목을 채웁니다.

Copy-Item .env.example .env

이미 .env가 있으면 기존 파일을 편집합니다. 아래 값은 예시이며 실제 키로 교체해야 합니다.

TABPFN_TOKEN=tabpfn_token_here
HF_TOKEN=hf_token_here
LLM_ANALYSIS_MODE=simple
OLLAMA_HOST=127.0.0.1
OLLAMA_EXPERT_MODEL=gemma4:12b
OLLAMA_DECISION_MODEL=gemma4:12b
NVIDIA_TOKEN=your_nvidia_api_key_here
NVIDIA_MODEL=nvidia/nemotron-3-super-120b-a12b
OLLAMA_TIMEOUT_SECONDS=600

.env는 Git에서 제외됩니다. 실제 인증 키는 코드나 README에 작성하지 않습니다.

ML 모델 인증

LSTM은 Hugging Face 토큰 없이 실행할 수 있습니다. TabPFN은 사용하는 모델 저장소의 접근 권한과 인증 조건에 맞춰 TABPFN_TOKEN, HF_TOKEN을 설정합니다. 코드에서는 TabPFN 사용 시 환경변수를 확인하고 HF_TOKEN으로 Hugging Face 로그인을 시도합니다.

TabPFN 미설치 또는 실행 실패 시 해당 예측만 생략하고 LSTM 분석을 계속합니다. 로컬 학습에 쓰는 TabPFN과 전문 분석에 쓰는 NVIDIA LLM은 서로 다른 모델입니다.

간단 분석: Ollama

Ollama를 설치하고 서버를 실행한 뒤 설정한 모델을 내려받습니다. 기본 모델 설정은 gemma4:12b입니다.

ollama pull gemma4:12b
ollama list

Ollama 앱 또는 ollama serve로 서버가 실행되어 있어야 합니다. OLLAMA_HOST에는 127.0.0.1 또는 다른 Ollama 서버의 호스트 이름/IP를 입력합니다. 현재 코드는 http://호스트:11434/api/generate를 구성하므로 프로토콜이나 포트를 포함하지 않습니다.

OLLAMA_EXPERT_MODEL은 두 전문가, OLLAMA_DECISION_MODEL은 최종결정자의 모델입니다. 모델을 변경할 때는 해당 태그를 Ollama에 설치하고 두 설정을 필요에 맞게 수정합니다. 각 호출 후 모델 메모리를 해제하는 요청을 보내므로 다음 호출에서 모델 로딩 시간이 발생할 수 있습니다.

전문 분석: NVIDIA API

NVIDIA API 키를 .env의 NVIDIA_TOKEN에 입력하고 전문 분석을 선택합니다. 기본 모델은 nvidia/nemotron-3-super-120b-a12b이며 https://integrate.api.nvidia.com/v1/chat/completions로 요청합니다.

전문 분석에서는 세 페르소나 모두 NVIDIA_MODEL을 사용합니다. Ollama 서버는 필요하지 않으며 역할별 가격·예측 요약 또는 뉴스 자료가 NVIDIA 서버로 전송됩니다. API 사용 가능 여부와 한도는 계정 및 서비스 조건에 따릅니다. 키 누락 시 전문 분석을 시작할 수 없고 요청 실패 시 로컬 모델로 자동 전환하지 않습니다.

연결 제한은 15초입니다. 응답 대기 제한 600초는 LLM 요청 하나에 적용되며 ML 학습과 전체 실행 시간의 상한이 아닙니다. 더 오래 기다리려면 .env에서 OLLAMA_TIMEOUT_SECONDS를 늘린 뒤 다시 실행합니다. 콘솔에는 호출별 입력 문자 수, 대기 제한, 응답 소요 시간이 출력됩니다.

전문가별 전달 정보

3년치 원시 일봉 전체를 LLM에 보내지 않습니다. 이 데이터는 로컬 ML 학습에 사용하며 페르소나에는 역할별 요약을 전달합니다. 전문가 호출은 순차적으로 수행합니다.

페르소나 | 전달 자료
주식전문가 | 기준 종가·날짜, RSI, 최근 5거래일 종가, LSTM·TabPFN T+1·T+4·T+7 예측가와 목표일, 모델별 MAE·naive MAE·방향 정확도·기준 미달 경고
뉴스기업전문가 | 종목명, 수집 기사별 언론사·제목·게시일·본문 또는 요약/제목
최종결정자 | 종목명, 두 전문가의 의견·점수 및 분석 실패 상태
전문 분석의 주식전문가에게는 실제 사전 T+1 예측의 방향 적중률과 평가 건수를 추가합니다. DB에 실제 종가가 저장된 과거 기록 중 저장 날짜가 목표일보다 앞선 기록을 대상으로, 목표일별 최신 기록을 선택하고 최대 최근 30개 목표일을 사용합니다. 평가 기록이 없으면 없다고 전달합니다. 현재 LLM 실행은 이 실제 종가를 새로 수집하지 않으며 T+1 성과를 T+4·T+7의 성과로 해석하지 않습니다.

전체 OOS 전략표, 자산 곡선, 매매 기록, HTML 리포트는 LLM 입력에 포함하지 않습니다. 주식·뉴스 의견은 각각 최대 699자, 최종 의견은 최대 500자로 저장합니다. 이 제한은 출력 의견 길이이며 입력 데이터 길이 제한이 아닙니다.

응답 마지막의 비어 있지 않은 줄은 {"score": 0.5}처럼 score 하나만 가진 JSON이어야 합니다. 숫자 범위는 -1.0~1.0입니다. 중복 키·문자열·불리언·범위 오류·JSON 뒤 추가 텍스트는 파싱 실패로 처리하며 실패 점수는 중립 0.0과 구분해 NULL로 저장합니다. 전문가 일부가 실패하면 최종결정자에게 실패 상태를 전달합니다.

데이터와 ML 검증

- yfinance에서 최근 3년의 조정 일봉과 USD/KRW(KRW=X), SOX(^SOX)를 수집합니다.
- 정규장 종료 전의 미완성 당일 일봉은 제외합니다. 한국·미국 마감 시각을 UTC로 비교하고 주가 마감 전에 확정된 거시지표만 merge_asof로 결합합니다. 결측치는 과거 값으로만 채웁니다.
- LSTM은 최근 30거래일의 종가·환율·SOX를 입력으로 T+1·T+4·T+7 가격을 동시에 예측합니다. 기본 hidden size는 32, 계층 수는 1입니다.
- TabPFN은 최근 10거래일의 가격·환율·SOX·RSI·EMA20·거래량을 사용하며 예측 기간별 회귀 모델을 학습합니다.
- 초기 70%를 시작 학습 구간으로 두고 이후 구간을 3개 walk-forward fold로 평가합니다. 학습 구간을 누적 확장하고 미래 구간에서 검증합니다.
- MAE·RMSE·MAPE·방향 정확도, fold별 결과와 평균·표준편차를 계산합니다. 직전 종가를 그대로 예측하는 naive baseline과 비교하고 기준 미달 경고를 저장합니다.
- 검증 후 전체 과거 데이터로 최종 모델을 다시 학습해 최신 예측을 생성합니다. 검증 결과는 analysis_log의 모델별 JSON 컬럼에 저장됩니다.

학습 설정은 ml_stock.py에서 조정합니다. 환경변수나 실행 인수로 바꾸는 항목은 아닙니다.

예측 기준일과 목표일

data_date는 마지막 확정 일봉의 날짜입니다. target_t1, target_t4, target_t7은 그 이후 1·4·7번째 거래일이며 달력상의 날짜 간격과 다릅니다. trading_dates.py는 XKRX/NASDAQ 거래소 달력으로 주말·휴장일을 처리합니다. 달력 계산 오류 시 평일로 추정하지 않고 해당 분석을 실패 처리합니다.

OOS 전략 비교는 T+1·T+4·T+7 실제 정답이 모두 확보된 공통 검증 표본의 T+1 날짜를 기준으로 합니다. 따라서 최근 6거래일은 평가에서 제외되며 OOS 종료일이 최신 확정 일봉보다 앞서는 것은 데이터 갱신 실패를 뜻하지 않습니다.

OOS 전략 백테스트

backtesting.py는 최종 재학습 모델이 아닌 walk-forward 테스트의 T+1 예측을 사용합니다. 전일 종가 대비 예측 상승률이 0.5% 초과면 다음 시가에 매수하고 0% 이하면 다음 시가에 매도합니다. 중간 구간에서는 기존 포지션을 유지하며 공매도·레버리지 없이 소수점 주식으로 전액 매수합니다.

LSTM·TabPFN의 공통 OOS 날짜로 비교하며 TabPFN이 없으면 LSTM 날짜를 사용합니다. 신호가 없는 구간은 다음 시가에 청산하고 현금으로 대기합니다. 같은 기간의 RSI 전략(전일 RSI 35 미만 매수, 65 초과 매도)과 단순 보유를 함께 계산하며 마지막 날 종가에 청산합니다.

편도 수수료 10bp(0.10%), 슬리피지 5bp(0.05%)를 적용합니다. Sharpe는 무위험 수익률 0, 연 252거래일 기준이고 MDD는 최초 자산 1부터 계산합니다. 세금·환전·배당 현금흐름·호가 유동성은 별도로 모델링하지 않습니다. 콘솔의 수익률·Sharpe·MDD·주문 수와 자산 곡선·주문 기록은 모델 검증 JSON에 저장됩니다.

기존 전체기간 RSI 백테스트는 비용 미반영이며 Sharpe 계산에 연 3% 기준을 사용합니다. 동일기간 OOS 비교와는 기간·비용·계산 기준이 다르므로 수치를 구분해서 읽어야 합니다.

뉴스 수집 및 선별

Google News RSS를 영문·미국 지역 설정으로 검색합니다. 회사 검색어는 삼성전자 Samsung Electronics, 엔비디아 NVIDIA, 인텔 Intel입니다. 삼성전자도 같은 영문 수집 경로를 사용합니다.

Bloomberg, Wall Street Journal, Financial Times, Reuters에서 조건에 맞는 기사 최대 1건씩 선택합니다. 최근 14일 이내, 회사명 관련성, 실적·자본정책 / 반도체·수요 / 계약·투자 / 규제·생산 위험 키워드와 최신성을 기준으로 순위를 정합니다. 이 점수는 기사 선별 기준이며 검증된 주가 영향도나 수익률 예측값이 아닙니다. 회사 관련 기사이므로 사업·노조·규제 뉴스도 조건을 만족하면 포함됩니다.

googlenewsdecoder로 원문 주소를 확인하고 trafilatura로 본문을 추출합니다. 기사당 본문은 최대 2,500자로 제한합니다. 접근 제한이나 본문 추출 실패 시 확보 가능한 요약 또는 제목으로 대체합니다. 선택된 기사가 없으면 같은 선별 기준으로 확보한 제목 최대 3개를 사용하고 그마저 없으면 뉴스 근거 부족으로 전달합니다. 현재 뉴스 수집 경로는 Yahoo Finance 뉴스가 아닙니다.

저장소와 기록 관리

database.py가 SQLite 연결과 경로를 공통 관리합니다.

- Windows 기본 경로: %LOCALAPPDATA%\StockAIDashboard\stock_analysis.db
- LOCALAPPDATA가 없는 환경: 프로젝트 폴더의 StockAIDashboard/stock_analysis.db
- 기본 경로에 DB가 없고 프로젝트 폴더에 기존 stock_analysis.db가 있으면 한 번 복사합니다.
- WAL 모드, 연결 대기 30초, busy_timeout=30000을 사용합니다.

별도 DB 경로는 Python 실행 전에 터미널 환경변수로 지정합니다. 현재 모듈 로딩 순서에서는 .env의 DB_PATH만으로 경로가 적용되지 않을 수 있으므로 다음 방식을 사용합니다.

$env:DB_PATH = Join-Path (Get-Location) 'data/stock_analysis.db'
python llm_stock.py --mode simple

analysis_log에는 ML 예측·검증·기준일·목표일을 저장하고 persona_discussion_log에는 의견·점수·run_id·analysis_id를 저장합니다. 같은 토론은 run_id, 해당 ML 결과는 analysis_id로 연결합니다. 각 전문가 답변은 다음 호출 전에 즉시 저장하므로 중간 실패 시 이미 받은 결과는 남습니다. 기존 기록의 누락된 날짜나 연결값은 추측해서 채우지 않습니다.

forecast_tracking.py는 목표일 개장 전 저장된 T+1 예측을 실제 확정 종가와 비교하고 평가 결과를 저장하는 모듈입니다. 독립 실행 명령은 없으며 호출 시 실제 가격을 조회합니다. LLM 전문 분석은 이미 DB에 저장된 실제 종가를 읽어 방향 성과를 요약합니다. 현재 평가 모듈은 저장 시각을 한국 시간으로 해석하므로 실행 컴퓨터의 시간대도 Asia/Seoul에 맞춰 사용합니다.

자동 보관 기간 및 수동 정리

ml_stock.py, llm_stock.py가 정상 종료하면 30일 이전 기록을 자동 정리합니다. 종목별 최신 ML 기록과 보호 대상 ML에 연결된 전문가 기록, 최근 또는 날짜 미확인 전문가가 참조하는 ML 기록은 보존합니다. 따라서 최신 분석은 30일이 지나도 남을 수 있습니다.

보관 기간 정리를 미리 확인하거나 적용하려면:

python cleanup_history.py
python cleanup_history.py --yes

실패한 LLM 기록만 확인하거나 삭제하려면:

python delete_sqlite.py
python delete_sqlite.py --yes

두 도구 모두 --yes 없이 실행하면 삭제 대상만 보여줍니다. --db로 별도 DB 파일을 지정할 수 있습니다. 실패 기록은 NULL 점수나 명시적인 분석 실패 의견 등으로 구분하며 정상 중립 점수 0.0은 삭제하지 않습니다.

t1_report.js는 생성 HTML에 포함되는 차트 코드이므로 ml_visualize_t1.py와 함께 유지합니다. PNG는 생성하지 않습니다. Chart.js를 CDN에서 불러오므로 차트 표시에 인터넷 연결이 필요합니다. 실제 종가 배열이 없는 기존 기록에서는 가격 차트 일부가 표시되지 않을 수 있습니다.
